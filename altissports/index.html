Developed Asset · Reference Infrastructure

AltisSports

A governed knowledge and evidence infrastructure for understanding spatial athletic systems across physical, virtual, distributed, human, machine, and hybrid environments.

Current state: Reference architecture and descriptive evidence infrastructure. ASR-001 remains an unpublished Working Draft under controlled external-review preparation.

01The problem it organizes

Spatial Sport is emerging through disconnected products and practices — immersive training, motion competition, mixed-reality exercise, remote embodied play, sensor-mediated measurement, simulated officiation. The field lacks a stable shared way to distinguish, compare, and govern these systems, so simulation gets confused with sport, immersion with embodiment, and device output with calibrated evidence.

AltisSports exists to organize that: to produce the governed language, evidence structures, reference architecture, and machine-readable objects through which spatial athletic systems can be described, compared, and reasoned about — deliberately not another sports publication.

02What exists today

AS³ Reference Architecture

A ten-layer inspection architecture for where a system enables performance, carries rules, senses, measures, officiates, and can lose integrity.

Boundary Case Corpus

Twenty stratified, evidence-linked cases (BC-001–BC-020) testing the category against ordinary, edge, support-system, automation, and computational cases.

Descriptive Atlas

Twenty records derived 1:1 from the corpus, preserving per-field claim class and status — a descriptive map, not a ranking.

Stable Identifiers

Sixty-nine stable governed identifiers; 39 are currently registered as externally citable canonical objects. Each carries claim class, license, temporal status, and a falsifiability reference.

Machine-Readable Distributions

A deterministic query contract, per-record JSON distribution, and resolver indexes — fetchable object by object.

ASR-001 Working Draft

A candidate evidence-profile specification for documenting one bounded, versioned system configuration. Unpublished; provisional.

Hosted Validation

A fail-closed continuous-integration gate with reproducibility checks and negative controls over every layer above.

03The reference model

Sources→ Evidence→ Corpus→ AS³→ Atlas→ Query Surface→ Citation

Every object added downstream has a known place, an identifier, a source, a temporal status, a claim class, and a correction path. The asset is a chain of governed objects — not a collection of articles.

04Trust & provenance

The basis for assessing the material is how it is built, not an appeal to authority:

  • Claim classes — documented fact, synthesis, attributed claim, and Altis interpretation are marked, never blended.
  • Source separation — what a provider says is kept distinct from what AltisSports concludes.
  • Provisional status — draft and candidate material is labeled as such, explicitly.
  • Falsifiability — each finding states what evidence would change it.
  • Identifier stability — identifiers are locked to meaning and not silently repointed.
  • Reproducible validation — artifacts are deterministic and checked in hosted CI.

06For humans and machines

  • Researchers can inspect evidence and the claim class attached to it.
  • Engineers can resolve structured records by stable identifier.
  • Journalists can trace each claim to a source and its status.
  • Analysts can distinguish documented source fact from Altis interpretation.
  • AI systems can consume versioned, licensed, provenance-rich objects.

These are capabilities the infrastructure supports. They are stated as what the material makes possible, not as a claim about who currently uses it.
